# M3b-B - Boundary Relabeling (nearest incorrect class)

Last updated: 2026-10-28. Full run list (every run, best row in bold): `records/results/runs_RLbnd.md` (auto-generated by
`scripts/method_runs_table.py`). Chronology: `records/JOURNAL.md`.

## 1. Method and implementation
**Code:** `src/mu/unlearn/methods.py::boundary_relabel`, `neighbour_labels`, `forward_forget` (reference: `sample_repos/RUM-main/RUM-main/unlearn/boundary_sh.py`). Config key: `RLbnd` in `configs/methods.yaml`.

For every forget batch: (1) find a "nearest but incorrect" label `y_nb` for each forget image using the **frozen Original model**;
(2) fine-tune the current model with `CE(f(x), y_nb)`. Labels are recomputed every batch (on the augmented image), as in the repo.
Optional (our additions): a retain fine-tuning pass after each forget epoch (`use_retain`), BatchNorm handling options (`bn_mode`, `bn_mix_retain`, `bn_recalib`).

Neighbour search options (`nb_search`, all in pixel space [0, 1]):
| option | what it does | parameters |
|---|---|---|
| `fgsm` (paper / repo) | ONE sign-gradient step `x' = clip(x + eps * sign(grad_x CE(Original(x), y)))`, rounded to 1/255; `y_nb` = Original's prediction on x' (if still y: highest-scoring other class) | `eps` (repo 0.1) |
| `pgd` (ours) | iterative sign-gradient steps of size `eps/nb_steps` inside the L-inf ball of radius `eps`; each sample takes the FIRST wrong class it crosses into (nearest boundary along the path); if it never crosses: best other class at the end | `eps` 0.1, `nb_steps` 10 (step 0.01) |
| `logit2` (ours) | no perturbation: the Original's highest-scoring wrong class on the clean image | - |

## 2. Hyperparameter sources
- Boundary paper: one sign-gradient step with a "relatively large" bound (value not given; repo `bound = 0.1`), fine-tune lr 1e-5 for 10 epochs (stated for VGGFace2); CIFAR-10 experiments use All-CNN trained 30 epochs without our augmentation. Defined for **class forgetting only**.
- Weight Saliency paper (re-implementation "BS"): FGSM step 0.1, 10 epochs, lr search [1e-6, 1e-4].
- Common to all our runs: 10 epochs, batch 256, SGD momentum 0.9, weight decay 5e-4, random crop + flip, bf16. Retain-pass batch 256. BN mixed batch: one retain batch of 256 concatenated to each forget batch.

## 6. Issues found and how they were resolved
**(a) BatchNorm-statistics artifact (main finding).** The method trains only on forget batches. In BatchNorm train mode every
forward pass (i) normalises with the current batch's statistics and (ii) updates the stored running mean/variance
(`running = 0.9 running + 0.1 batch`), which are used at test time. With class-0-only batches the stored statistics become
airplane statistics within ~30 steps (0.9^30 = 4% of the old values remain). At test time every image is then normalised with
airplane statistics, which suppresses airplane-specific activations, so airplanes stop being recognised - without much weight change.
Evidence (S1, C0): relative weight change vs Original only **0.57%**, BN running mean **24.3%**, running var 14.8%;
re-estimating only the BN statistics on retain data (no weight change) brings forget acc back from 23.6% to **99.9%**;
C0 with mixed BN batches (BN never sees forget-only batches) forgets only to 54%. Neither the Boundary paper nor the other papers
mention BN statistics; the reference repo trains in BN train mode.
**Resolution:** (1) mixed BN batches (`bn_mix_retain`: a retain batch is concatenated to every forget forward pass; loss only on
the forget part) or (2) frozen BN statistics (`bn_mode=frozen`) - both make the forgetting come from weight updates and both
improve every configuration (C1 0.91 -> 0.49 / 0.52; C2 1.52 -> 1.31 / 0.77; C3 2.04 -> 1.56 / 1.18). Gradient clipping is not
needed for this method (frozen + clip is worse: it limits the useful updates). (3) Robustness check `+recal` is reported for the
best configurations: C1 stays forgotten after recalibration (1.33%) because its retain pass keeps BN calibrated; C2/C3 (no
retain pass) partially relapse (31% / 21%).

**(b) One-step FGSM with eps 0.1 does not find the nearest class.** Embedding check (`records/figures/fig_embed_S1c0__RLbnd__s0.png`,
`records/runs/<run>/embedding_check.json`): in the Original's feature space the nearest retain class for 84% of airplanes is
**ship**, but FGSM(0.1) assigns bird 2008, frog 1723, ship only 288 (the large step lands in noise-like "frog/bird" regions).
**Resolution:** iterative search (pgd: first class crossed) or logit2 (second-highest class: bird 1771, ship 1666, truck 366);
a smaller FGSM step (0.03) also works (C3), a larger one (0.3) is worse (C4).

**(c) Retain pass needs good labels.** With FGSM(0.1) labels plus a retain pass the model only reaches 13% forget acc (lr 1e-3);
with logit2/pgd labels 1-2%. Noisy neighbour labels conflict with the retain data; consistent labels do not.

**(d) Forget samples do not merge into the neighbour clusters in feature space.** After C1, 70% of forget samples have their
assigned class as majority among their 10 nearest neighbours (51% before) and 68% are predicted as the assigned class, but in t-SNE
they remain a separate cluster next to bird/ship (`records/figures/fig_embed_S1c0__RLbnd__imp_nb_searchlogit2_lr0.001_use_retain1__s0.png`).
A fresh linear probe on the frozen features still recognises class 0 at **95%** (NCC 93%; Retrain 88% / 41%).
Reason: CE with the neighbour label only requires the logits to cross the decision boundary; the cheapest way is to change the
classifier head and the last features slightly, after which the loss and its gradient vanish; no term pulls the features into
the neighbour cluster; the backbone barely changes (small lr, ~180 forget steps, retain pass); and airplanes relabeled to
different classes still share their airplane features. The Boundary paper's figures show the decision (output) space, where the
samples do move into the neighbour regions. Making the features merge would need an explicit feature-level loss (not tried yet).

**(e) S2 has no good setting** - see section 5.
